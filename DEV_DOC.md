# Developer Documentation

Purpose

- Explain how to build, run, debug and maintain the Inception stack.

Prerequisites

- Docker and Docker Compose V2 installed.
- User running the commands has permission to run docker (or use sudo).
- Populate environment variables in [srcs/.env](srcs/.env) before building.

Main files

- Make targets and orchestration: [Makefile](Makefile)
- Compose orchestrator: [srcs/docker-compose.yml](srcs/docker-compose.yml)
- Environment template: [srcs/.env](srcs/.env)
- Service Dockerfiles and scripts: [srcs/requirements](srcs/requirements)

Quick start (from repository root)

- Build images and start required services:

  ```sh
  make
  ```

  or:

  ```sh
  make build && make up
  ```

  (uses [`Makefile`](Makefile) which calls [srcs/docker-compose.yml](srcs/docker-compose.yml))

Useful make targets

- make up       — build (if needed) and start default services (nginx, mariadb, wordpress, redis, adminer, docs)
- make build    — build images only
- make down     — stop and remove containers
- make fclean   — remove containers, images and volumes
- make re       — full rebuild (fclean then up)
See [`Makefile`](Makefile) for the full list.

Environment and persistence

- Fill required variables in [srcs/.env](srcs/.env) before first run. Important variables:
  - DATA_DIR — host directory used for persistent data (used by volumes)
  - DOMAIN_NAME — domain used to generate certificates and site URL
  - DB_ROOT_PASSWORD, WP_DB_*, WP_ADMIN_* etc.
- Volumes are bind mounts pointing to ```${DATA_DIR}/mariadb``` and ```${DATA_DIR}/wordpress``` as configured in [srcs/docker-compose.yml](srcs/docker-compose.yml). Inspect mounts on running containers with:

  ```sh
  docker inspect --format '{{ json .Mounts }}' wordpress
  ```

  ```sh
  docker inspect --format '{{ json .Mounts }}' mariadb
  ```

Common commands

- See running containers:

  ```sh
  cd srcs && docker compose ps
  ```

- Follow logs:

  ```sh
  cd srcs && docker compose logs -f
  ```

- Open a shell inside a container:

  ```sh
  docker exec -it wordpress /bin/sh
  ```

  ```sh
  docker exec -it mariadb /bin/sh
  ```

  ```sh
  docker exec -it nginx /bin/sh
  ```

- View health status:

  ```sh
  docker inspect --format='{{json .State.Health}}' `container`
  ```

Database access (example)

- From host: use the mariadb container's client:

  ```sh
  docker exec -it mariadb mariadb -u root -p"$DB_ROOT_PASSWORD" -e "SHOW DATABASES;"
  ```

- From php container (if mysql client installed):

  ```sh
  docker exec -it wordpress mysql -h mariadb -u ${WP_DB_USER} -p${WP_DB_PASSWORD} ${WP_DB_NAME}
  ```

Rebuild / release workflow

- Build images for CI / local: make build
- Recreate everything clean: make re

Bonus services

- Build & start additional bonus services (ftp, dozzle):  

  ```sh
  make bonus
  ```

- Dockerfiles for bonus services live under: srcs/requirements/bonus/* (adminer, dozzle, ftp, docs, redis).
- Note: Dozzle and FTP are bonus services and are not started by the default `make`. Run `make bonus` to enable them.
- Access points:
- Redis: the WordPress container uses the REDIS_HOST/REDIS_PORT env vars (set in [srcs/.env](srcs/.env)). Use `docker exec -it redis redis-cli` for troubleshooting.
  - Adminer: [localhost/adminer.php](https://localhost/adminer.php) (nginx proxy)
  - Docs static site: [localhost/Docs](https://localhost/Docs) (nginx proxy)
  - Dozzle: [localhost:8081](http://localhost:8081) (bound to localhost only)
  - FTP: localhost:21; uses wordpress volume as FTP home

Debugging tips

- If a service repeatedly restarts: check logs (make logs) and healthcheck definitions in [srcs/docker-compose.yml](srcs/docker-compose.yml).
- If nginx fails: check /var/log/nginx (inside container) and verify SSL certs are present (generated by [srcs/requirements/nginx/tools/start-nginx.sh](srcs/requirements/nginx/tools/start-nginx.sh)).
- WordPress setup issues: check that mariadb is healthy and WP environment vars in [srcs/.env](srcs/.env) are correct.

Secrets and environment handling

- Current setup uses [.env](srcs/.env).

Container restart policy and best practices

- Compose sets restart: unless-stopped. Check each service in [srcs/docker-compose.yml](srcs/docker-compose.yml).
- Entrypoints are shell scripts that exec the final process.
